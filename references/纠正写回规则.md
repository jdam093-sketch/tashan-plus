# 纠正写回规则

## 1. AI 不直接改技能

使用技能时，AI 不直接改已装技能或母本里的任何文件。用户明确委托改版时，维护者仅在获准的新版本工作副本中修订；安装、同步、发布不由改版授权自动涵盖。

## 2. 当次照办、草稿留存、中央登记

1. 用户指出技能的问题，当次按其要求调整做法，不直接改技能。普通内容修改不记为技能问题；拿不准就记“可能只针对本次”。复核/审核发现也可记录，不能伪称用户原话。
2. 先在**当次任务 output 的 `待吸收意见-草稿.md`** 末尾追加，格式见 [待吸收意见模板](../待吸收意见.md)。没有任务文件夹时，按 SKILL.md 第八节把草稿写到获准目录内的 `他山-YYYYMMDD-主题/`，不写母本。
3. 每条草稿都在**中央登记册**追加一行：`日期 | 草稿路径 | 一句话 | 状态`。草稿路径须能定位文件和条目编号；初始状态“待吸收”。登记册为**维护者指定的登记文件**。无任务文件夹也照样登记。
4. 未指定登记文件、路径不可写或当前授权禁止写时，保留草稿并标“待登记”，向用户说明缺口；不另起一个冒充中央登记册，不越权写入，也不声称登记完成。获得路径和写入授权后补登记。
5. 汇报草稿路径、登记结果与未完成事项。登记册只放索引，不复制敏感原文；草稿本身也遵守隐私规则。

## 3. 何时统一改版

未吸收意见攒约 5 条，或最早一条满一个月，由维护者按中央登记册收集去重，汇总进获准新版目录的 `待吸收意见.md`。其它助手只提醒。复核/审核意见计入有效未吸收条数；同一问题不因多处登记重复计数。

## 4. 怎么改

1. 在获准输出位置新建下一版本，旧版不改、不删、不覆盖，母本只读约束仍有效。
2. 正文文件头改版本号和日期；SKILL.md 的版本行放在 YAML frontmatter 之后。**LICENSE 保持 MIT 正文和版权行，不加版本头**；机器配置不得塞入正文版本行。
3. 更新 CHANGELOG.md，列出对应意见与变化；写“改了什么”清单，逐条列意见编号 → 文件与位置 → 改前/改后，未采纳项写理由。
4. 把新版与清单交用户检查；不把自查当独立最终放行。

## 5. 用户回“可以”才生效

未确认前只是待批稿，不安装、不同步。用户明确确认后，在获准的新版汇总记录中更新条目状态为“已吸收进 vN”或“不采纳（理由）”，中央登记册追加对应状态行，保留历史；不得借此写入只读母本。计数取同一条目的最新状态。既有明确授权可以作为本次“可以”，不重复索要。

## 6. 按版本同步

由维护者按当前项目规则分工，只有获准安装、同步时才执行；各处使用同一版本，按正文版本号及文件哈希核对。LICENSE 不加版本头。不得在不同安装处各自修改，不未经授权发布或推送。
